## AI Agent 优化记录

本节持续记录健康档案问答助手的优化。这里的“Agent”指当前项目中的资料检索、对话上下文和记忆能力；目前没有自主规划并调用多种工具的执行流程。

### 从单轮问答到持续对话

**最初做法**：用本轮问题加上一轮用户问题检索 Markdown 档案，按关键词和中文双字片段匹配选出最多 8 个片段；将片段和固定写在代码中的规则发给模型，等待完整回答后一次返回。聊天记录通过 JDBC 写入数据库，但回答模型没有收到完整会话历史。

| 优化 | 当前做法 | 相比最初的收益 |
| --- | --- | --- |
| 流式回答 | 后端以 SSE 逐段发送回答，前端边接收边展示，并在完成事件中取得会话编号和引用来源。 | 长回答可以更早开始展示；用户可逐段阅读。 |
| 停止生成 | 原先生成期间只能等待回答完成。现在按钮可停止本轮：前端取消请求并移除临时问答、保留输入；后端接收停止信号后取消模型流，并跳过本轮会话和记忆写入。 | 预期可在发现问题有误时尽早结束生成，避免未完成回答进入历史；尚未运行验证，也未量化节省的模型调用量。已经完成数据库写入的回答不能追溯取消。 |
| 会话上下文 | 问答消息按登录账号、成员和会话保存；回答时传入近期原始消息，并将较早消息压缩为会话摘要。 | 连续追问时能参考更多上下文；摘要控制长会话传给模型的内容量。 |
| 跨会话记忆 | 从用户原话提取偏好与健康自述，按账号和成员保存；提问时筛选相关项，用户可查看、修改和删除。 | 新会话可参考已表达的偏好和自述，减少重复说明。健康自述标为未核实，不能代替档案依据。 |
| 系统提示词管理 | 系统提示词保存在数据库中，通过接口读取和更新；问答时作为系统消息传给模型。 | 调整回答规则不必修改问答逻辑。 |
| 中文档案检索 | 用中文分词提取检索词，结合词项在档案中的稀有程度打分，并提高本轮问题的权重；汇总本会话历史用户问题辅助检索，过长时压缩。 | 设计目标是减少简单字串匹配带来的偏差，并改善多轮追问的检索相关性；尚无对比数据证明效果。 |

回答仍以本轮检索到的健康档案片段为依据；会话摘要、聊天历史和跨会话记忆只用于理解问题与指代。没有找到相关记录时，系统明确提示资料不足。以上收益是根据实现机制得出的预期与体验变化，尚未进行回答质量或性能的量化对比。

实现细节见[问答记忆机制](问答记忆机制.md)、[流式对话与 SSE](流式对话与SSE.md)、[Spring AI 在项目中的使用](Spring AI在项目中的使用.md)；主要代码见 [`HealthController.ask`](../ruoyi-admin/src/main/java/com/ruoyi/health/HealthController.java)、[`HealthMemoryService`](../ruoyi-admin/src/main/java/com/ruoyi/health/HealthMemoryService.java) 和 [`HealthFiles.search`](../ruoyi-admin/src/main/java/com/ruoyi/health/HealthFiles.java)。
