# 问答记忆机制（当前实现）

## 结论

当前资料问答支持**会话记录持久化**和**上一轮用户问题的上下文引用**，但没有独立的“记忆模式”开关，也没有长期记忆提取、用户画像或完整多轮消息上下文。健康档案是每轮问答都会检索的持久化资料，不等同于聊天记忆。

## 一次提问的处理流程

1. 前端提交成员、问题、模型编号和当前 `conversationId`。新对话提交空编号；继续历史对话提交已有编号。
2. 后端在编号为空时生成 UUID，并按成员和会话编号查询**最近一条用户问题**。
3. 检索健康档案时，将上一条用户问题与本轮问题拼接为检索文本；没有上一条问题时只使用本轮问题。
4. 从该成员的 Markdown 档案中选出最多 8 个相关片段。模型提示词包含上一轮问题、本轮问题和这些档案片段。检索不到片段时直接返回“当前档案中没有找到足够的相关记录”，不调用问答模型。
5. 后端将本轮用户问题、助手回答及引用来源写入数据库，并返回会话编号。前端用返回的编号继续当前对话。

关键实现：[`HealthController.ask`](../ruoyi-admin/src/main/java/com/ruoyi/health/HealthController.java)、[`HealthFiles.search`](../ruoyi-admin/src/main/java/com/ruoyi/health/HealthFiles.java)、[`submitQuestion`](../../ruoyi-fast-vue3/src/views/health/index.vue)。

## 数据保存与历史查看

`health_chat_message` 表以 `conversation_id` 和 `member` 关联消息；每条消息包含角色、内容、来源及创建时间。一次问答会写入一条 `user` 消息和一条 `assistant` 消息。表结构见 [`health.sql`](../script/sql/health.sql)，写入逻辑见 [`HealthChatMapper`](../ruoyi-admin/src/main/java/com/ruoyi/health/mapper/HealthChatMapper.java)。

历史会话列表按最近活动排序，最多展示 30 个会话，标题取该会话的第一条用户问题。打开会话时，接口按消息编号升序读取最多 100 条消息供前端展示。点击“新对话”会清空前端当前会话编号和消息列表；下一次提问会创建新会话。

## 记忆范围与限制

| 内容 | 当前行为 |
| --- | --- |
| 当前会话的上一轮用户问题 | 参与档案检索，并作为提示词中的“上一轮问题”。 |
| 更早的用户问题、历史助手回答 | 保存在数据库供查看，但不传给模型生成本轮回答。 |
| 其他会话的聊天内容 | 不参与本轮检索或模型提示词。 |
| 健康档案 Markdown | 每轮按当前成员检索相关片段，可跨会话使用。 |
| 聊天中新增的健康事实或偏好 | 不会自动写入健康档案，也不会形成独立的长期记忆。 |

因此，连续追问可以借助**紧邻上一轮的问题**获得部分上下文；如果本轮只说“那后来呢”，且需要依赖更早的回答或多轮对话信息，当前实现可能无法正确理解。检索和回答仍以成员档案中的资料为依据。

## 对应接口

- `POST /health/ask`：提交问题并返回 `conversationId`、回答和引用来源。
- `GET /health/conversations?member=...`：读取该成员最近会话列表。
- `GET /health/conversations/{id}?member=...`：读取该成员指定会话的消息。

接口定义见 [`HealthController`](../ruoyi-admin/src/main/java/com/ruoyi/health/HealthController.java)。
